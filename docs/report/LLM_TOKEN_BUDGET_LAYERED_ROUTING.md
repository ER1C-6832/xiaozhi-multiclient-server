# LLM Token 分层预算与工具路由交付报告

## 问题证据

2026-07-28 的真实“你好”请求由供应商返回 `8253` 输入 Token、`13`
输出 Token。请求同时携带 38 个工具、12423 字符工具 Schema、6690
字符系统提示和工具 few-shot。工具实际执行数为 0。

## 已实现

- 普通聊天使用无工具快路径。
- 普通聊天使用紧凑系统提示和双重有界历史。
- 本地确定性路由根据明确领域与动作从工具元数据筛选候选，不产生额外云调用。
- 每次最多 3 个候选工具，候选 Schema 总长度不得超过 5000 字符。
- 模糊请求默认普通聊天，不把全量工具暴露给模型。
- 工具结果以有界安全摘要进入 follow-up；follow-up 强制 `tool_count=0`。
- 请求发出前校验消息字符数、工具数量和 Schema 字符数。
- chat/tool 使用独立预算并在日志、WebSocket、PC Developer 诊断中显式展示。

## 当前默认预算

| 项目 | 普通聊天 | 工具请求 |
|---|---:|---:|

## 真实验收

普通文本链路：

- provider input: 470
- provider output: 4
- total: 474
- request_route: chat
- tool_count: 0
- tool_schema_chars: 0
- system_chars: 789

相比原始 8266 Token，总量降低约 94.3%。

最终镜像同口径发送字面“你好”：451 输入、10 输出、461 总计，
`selected_tool_count=0`、`selected_tool_schema_chars=0`，相比原始结果降低约 94.4%。

天气工具链路：

- 第一调用：682 输入、17 输出、1 个候选工具、426 字符 Schema
- 工具结果 follow-up：486 输入、14 输出、0 个工具、0 字符 Schema
- 整轮：1199 Token、2 次 LLM、1 次工具

## 边界

- 本地路由以成本与安全优先。没有明确工具领域的请求不会加载工具，必要时由模型澄清。
- 当前未实现跨会话、按用户或按日持久化额度；该部分留作正式商业部署的财务保护。
- Provider 返回的实际 usage 仍是最终权威统计。请求前结构闸门不伪装成精确 Tokenizer。
